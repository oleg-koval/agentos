Update control

Storage

Encryption is the physical-install default.

The physical installer defaults to LUKS2 and creates a Btrfs layout with dedicated subvolumes and compression. The VPS bootstrap does not partition or format disks.

Recovery

Root and boot state move together.

The pacman hook captures both a root snapshot and its matching systemd-boot entry, kernel, and initrd bundle; the rollback tool stages a one-shot entry.

Who it is for—and who it is not for

Good fit

  • Developers who want a reproducible Arch workstation for AI-assisted development
  • AI-agent power users who need persistent sessions, health visibility, and deliberate tool updates
  • Homelab operators comfortable with Linux, SSH, snapshots, and explicit maintenance
  • Operators of already-provisioned Arch Linux x86_64 VPS hosts with systemd and pacman

Not a fit

  • Anyone looking for a new AI operating system or a replacement for the Linux ecosystem
  • Operators who require a maintenance model other than AgentOS’s channel-gated stable schedule
  • Non-Arch VPS hosts, managed platforms, or hosts without an existing non-root SSH user
  • Anyone who cannot safely back up and dedicate a physical target disk to the installer

Reasonable concerns, explicit boundaries

“The installer looks destructive.”
It is. The physical installer requires an explicit target disk and deliberate erase confirmation (Cancel is the interactive default). Use the separate VPS path for an already-provisioned Arch host.
“Arch updates can break a working machine.”
Stable updates are scheduled weekly, attempt a pre-transaction snapshot, run post-update health checks, and arm a next-boot health gate when a recovery point exists. Snapshot failure does not currently abort the update. Other channels skip scheduled updates, and manual inspection/apply commands remain available.
“Will this work on my VPS?”
The documented target is an already-provisioned Arch Linux x86_64 host with systemd, pacman, SSH, and a non-root user. The provider matrix currently records Google Cloud validation; AWS and Hetzner remain pending.
“Does this lock me to one vendor?”
The source repository is configurable, VPS bootstrap is provider-neutral, and agent capabilities are explicit selections. AgentOS still relies on Arch Linux and whichever agent services you choose.
“Is the native shell required?”
Native Workspace is the documented default graphical surface after its authorized QA path. Chromium Home remains installed as the recovery fallback, and headless VPS operation remains available over SSH.

Frequently asked questions

Does AgentOS update Arch automatically?

The stable channel schedules a weekly update on AC power. Beta, edge, and none skip scheduled updates. Use agentos update --check to inspect and agentos update --apply for a manual run.

Does the VPS installer erase disks?

No. The VPS bootstrap expects an already-provisioned Arch host. It does not install an operating system, partition or format disks, change the firewall, alter sshd, or reboot the host.

What does read-only VPS onboarding check?

It checks SSH, signed-repository state, installed AgentOS packages, the localhost API, and the graphical Home service when a Wayland session exists. It does not repair packages, restart services, or change access policy.

How does rollback avoid kernel mismatch?

The pre-pacman process stores the Btrfs root snapshot together with matching systemd-boot, kernel, and initrd files. A staged rollback uses dedicated recovery files for the next boot only.

Is Secure Boot enabled automatically?

No. The repository lists Secure Boot with signed boot artifacts as remaining hardening. It is intentionally not auto-enabled because key enrollment changes firmware trust state.

Where do I start when something is unhealthy?

Start with agentos health, agentos state, and agentos repository status. The troubleshooting guide keeps inspection separate from repair.
